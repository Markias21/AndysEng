- 2026-08-02 | **새 상단 탭 "🎧 3분 학습" — 짧은 리스닝+리딩 겸용, AI 완전 미사용 MVP.** `만들고 싶은 기능.md`(리스닝 미착수 항목의 "필요한 고려사항")에 리딩·리스닝 둘 다 지문이 길어 1~3분짜리 짧은 버전을 원한다는 메모가 있었다. 조사 결과 리딩 파이프라인이 이미 VOA 기사마다 mp3 오디오 링크(`audio` 필드)를 저장해 두고도 화면에서 전혀 안 쓰고 있었고, VOA에는 원래 짧은 프로그램(Words and Their Stories — 관용구 위주 주간 쇼, ~2~3분)이 텍스트+오디오를 함께 제공해 **짧은 리딩과 짧은 리스닝을 같은 콘텐츠 하나로 동시에 해결**할 수 있었다. 후보였던 News Words(어휘 위주)는 실제 확인 결과 비디오 시리즈라 본문 div·mp3가 없어(영상만 있음) 제외했다. **수집(신규, 리딩과 분리):** `scripts/fetch-voa-listening.js`가 `scripts/voa-parse.js`의 `LISTENING_CATEGORIES`(zone 987, feed `zmypyl-vomx-tpeyry_` — VOA rssfeeds 페이지에서 라벨·zone·feed가 한 `<li>` 블록 안에 함께 있어 이번엔 이전 경고(라벨-피드 밀림)에 걸리지 않았고, `<channel><title>`로도 재확인)를 돌려 `parseArticle`/`parseFeed`를 그대로 재사용하고, 분량 기준만 다르게 잡는다(150~600단어, 실측 300~500단어대). **오디오 없는 기사는 버린다**(이 기능의 핵심이 듣기이므로). `public/data/listening/`에 저장, `.github/workflows/voa.yml`이 리딩과 같은 커밋에 함께 수집. **채점(신규, AI 미사용 — 위시리스트 원안 "딕테이션은 AI 사용 X"과 일치):** `features/listening/dictation.js`(순수 함수)가 난이도별(초급=6글자 이상 내용어만·중급=내용어 전부·상급=불용어 포함 전부)로 빈칸을 고른다. **`shared/cloze.js`의 `buildCloze`는 재사용하지 않았다** — 표현 하나가 지문 전체에서 딱 한 번만 빈칸이 되는 텍스트 검색 방식이라, the/a처럼 흔한 단어가 한 문장에 여러 번 나오면 첫 등장만 잡히고 나머지는 유실된다(상급 = 전부 빈칸에서 특히 문제). 대신 위치를 아는 토큰을 직접 잘라 같은 출력 shape(`{translation, parts, blanks}`)을 만들어 `shared/cloze-view.js`(글자당 칸, 스페이스바 이동, 첫 글자 힌트)는 그대로 재사용했다. 채점은 `checkBlank` 재사용, 정답 여부만 로컬로 판정(0~100 AI 점수 없음). **화면:** 카테고리가 하나뿐이라 리딩과 달리 카테고리 그리드 없이 목록→연습 2단계, 연습 화면은 `<audio controls>` + 난이도 picker(`diff-picker`, 글쓰기 기본과 같은 스타일) + 받아쓰기 폼. **기록:** `records.listening`(신규, `store.js` `RECORD_KINDS`에 추가) `{articleId, category, difficulty, total, correct}` — score 없음. `stats.js` `dailyStats`는 `listenCount`만 세고(활동 카운트) 점수 평균·캘린더 등급 색칠에는 반영하지 않는다(무리하게 S~F 체계에 끼워 넣지 않음). 이해도 객관식(AI 생성)은 이번 범위 밖 — 사용자가 "받아쓰기만, AI 완전 미사용"을 선택. 헤드리스 브라우저로 목록·오디오 재생·난이도 전환(빈칸 수 936→1335 확인)·타이핑·채점·기록 표시·모바일 360px 무가로스크롤까지 실제 확인 | 사용자가 "리스닝 기능을 만들고 싶다"며 아이디어를 요청했고, 이어 "하는 김에 짧은 리딩도 가능한가?"라고 물어 콘텐츠 통합을 확정. AI 미사용으로 비용 0원인 채로 리딩·리스닝 두 가지 오래된 요청을 동시에 해소.

- 2026-08-04 | **새 상단 탭 "🎙 리스닝" — BBC 6 Minute English. 저작물 대본을 레포에 담지 않고 브라우저가 PDF를 직접 받아 파싱한다.** 위시리스트 8번의 마지막 미착수 항목(BBC 기반 본격 리스닝)을 만들었다. VOA와 달리 **BBC 콘텐츠는 퍼블릭 도메인이 아니라서**, VOA 파이프라인(본문을 레포에 커밋)을 그대로 복사하면 공개 레포·GitHub Pages에 저작물을 재배포하게 된다. 유저가 "레포에 저장하지 말고 그때그때 불러올 수 없나"라고 물어 실제로 조사해 보니 가능했다: **`downloads.bbc.co.uk`는 `access-control-allow-origin: *`을 준다**(오디오 mp3·대본 PDF 둘 다). CORS를 안 주는 곳은 에피소드 HTML 페이지뿐이다. 그래서 역할을 갈랐다 — **GitHub Actions는 페이지에서 링크만 긁어 커밋하고(`public/data/6min/index.json`: 제목·날짜·페이지/오디오/대본 URL, 저작물 텍스트 0), 대본은 앱이 열 때 브라우저가 BBC에서 PDF를 직접 받아 파싱한다.** 오디오도 BBC 링크로 스트리밍만 하고 재호스팅하지 않는다(위시리스트 원칙). 링크를 제목·날짜로 추측하는 방안은 실측에서 최근 12편 중 3편이 실패해(`_transcript_.pdf` 오타, 제목의 아포스트로피가 URL에 그대로 남음, `_download` 접미사 없는 mp3) 버렸다 — 반드시 페이지에서 읽는다.

  **PDF 텍스트 추출기를 직접 썼다(`shared/pdf-text.js`, 의존성 0개 유지).** 브라우저·Node 내장 `DecompressionStream("deflate")`가 곧 PDF의 FlateDecode다. 대상 PDF는 전 회차 규격이 같다(PDF 1.3 / TrueType + **MacRomanEncoding** / 오브젝트 스트림 없음). 핵심은 **`cm`·`Tm`을 곱해 얻은 y 좌표로 조각을 줄로 묶는 것**이다 — 이게 없으면 커닝 때문에 한 단어가 `word / - / for / - / word`로 쪼개진다. 줄 간격이 평소보다 벌어지면 문단 경계로 보고 빈 줄을 끼워, 다음 단계에서 화자 이름을 알아볼 단서로 쓴다. 겪은 함정 셋: (1) `/Subtype`이 있는 스트림(이미지)을 안 거르면 1MB 바이트열이 토크나이저에 들어가 **OOM으로 죽는다**. (2) `TextDecoder("latin1")`은 windows-1252로 해석돼 0x80~0x9F가 어긋난다 — 바이트↔문자 1:1이 필요하면 `String.fromCharCode`로 직접 만들 것. (3) **MacRoman 표는 정확히 128자여야 한다** — 눈에 안 띄는 0xCA(비분리 공백)·0xF0(애플 로고)을 빠뜨려 뒤가 한 칸씩 밀렸고 `–`가 `—`로 나왔다(테스트가 길이를 검사한다). 테스트는 BBC PDF를 커밋하지 않으려고 **코드에서 최소 PDF 바이트를 만들어** 검증한다.

  **대본 파싱(`sixmin/transcript.js`, 순수 함수):** 머리말·꼬리말(`©British Broadcasting Corporation`, `Page N of M` 등)과 심볼 폰트가 남긴 `!`를 걷어내고, **문단이 새로 시작하는 자리의 짧고 마침표 없는 줄**을 화자로 본다(대사 중간의 짧은 줄을 오인하지 않기 위해 "문단 경계" 조건이 필수). `VOCABULARY` 아래를 용어+영어 정의로 나눈다. 실제 40편 전체를 돌려 화자 턴·어휘 6개가 전부 깨끗이 나오는 것을 확인했다.

  **화면:** 오디오(속도 0.75x/1x, ⏪⏩5초) + **구간별 받아쓰기** + BBC 어휘 + 토플식 이해 문제. 대본에 타임스탬프가 없어 구간 시작 시각은 **`단어 위치 ÷ 전체 단어 × 오디오 길이`로 비례 추정**하고(`sixmin/segments.js`), 어림값임을 화면에 적고 ±5초 보정 버튼을 함께 둔다. 빈칸 선택·채점은 `features/listening/dictation.js`를 **`shared/dictation.js`로 승격**해 3분 학습과 공유하고, 입력칸은 기존 `shared/cloze-view.js` 그대로다(글자당 칸·스페이스바 단어 이동·첫 글자 힌트). 4지선다 채점은 `reading/score.js`에서 **`shared/mcq.js`로 승격**(`gradeChoices`/`validQuestions`/`comprehensionSummary`/`weakTypes`, `weakTypes`는 유형 이름표를 인자로 받게 일반화). BBC 어휘는 `➕ 복습에 추가`로 유저가 고르고, 이때 **그 표현이 실제로 등장한 대본 문장**을 예문으로 붙여(`exampleFor`) 복습 예문 빈칸이 곧바로 성립한다(한국어 뜻·해석은 없다 — 필요하면 기존 📖 사전으로).

  **AI는 이해 문제 생성 하나뿐**(에피소드당 평생 1회, `store.sixMinSets` 영구 캐시, 실측 **$0.0315**). 토플 iBT Listening 7유형(주제·목적·세부·발화 의도·태도·구성·추론, `sixmin/types.js`)에서 매번 다른 유형으로 5문제. 정답 키를 함께 받아 두므로 **채점·재도전은 0원**이고, 대본·어휘·받아쓰기·구간 재생도 전부 0원이다. 리딩과 같이 생성 전 `confirm()`으로 예상 비용을 안내한다(추정이 실제보다 싸 보이지 않도록 출력 토큰을 넉넉히 잡았다). **대본 캐시는 `store.js`가 아니라 별도 localStorage 키(`andyseng:6min-cache`, 최근 12편)에 둔다** — store는 GitHub 백업·동기화 페이로드에 통째로 실리므로, 개인 학습 기록과 달리 BBC 대본은 거기에 얹지 않는다.

  **곁들여 고친 기존 버그:** `index.html`의 CSP가 `default-src 'self'`인데 `media-src`가 없어, **2026-08-02에 넣은 🎧 3분 학습의 VOA 오디오가 배포 이후 줄곧 CSP에 막혀 재생되지 않고 있었다**(`media-src`는 `default-src`로 폴백한다). 옛 CSP를 그대로 쓴 테스트 페이지에서 `Refused to load media`를 재현해 확인했다. `media-src 'self' https://voa-audio.voanews.eu https://downloads.bbc.co.uk`를 신설하고 `connect-src`에 `https://downloads.bbc.co.uk`를 더했다. 인라인 `style="width:100%"`도 `style-src 'self'`에 막히고 있어 `.audio-player` 클래스로 옮겼다(3분 학습도 함께).

  검증은 `chrome-headless-shell`을 CDP로 직접 몰아(playwright 미설치, node 내장 WebSocket) 실제 앱에서 확인했다: 에피소드 40편 목록 → BBC PDF 실시간 파싱 → 오디오 길이 375초 로드(CSP 통과) → 구간 7개·추정 시각(00:00·00:45·01:32…) → 속도·⏪⏩·구간 점프 → 난이도별 빈칸 40/74/116 → 받아쓰기 채점·기록 → 어휘 ➕ → 🔁 복습에서 그 문장 빈칸으로 출제 → 문제 생성 취소($0)/확인($0.0315)/채점/재도전($0) → 모바일 390px 무가로스크롤. 기록은 `records.sixMin`(점수 없음), 통계는 활동 카운트만(3분 학습과 동일) | BBC 대본을 공개 재배포하지 않으면서도 받아쓰기·문제 생성을 다 하려면 이 구조뿐이었다. 유저가 "레포에 저장하지 말고 그때그때 불러올 수 없나"라고 먼저 물어 조사에 들어갔고, 그 결과 CORS가 열려 있어 가능하다는 것이 확인됐다.
